# 排盘准确性验证报告（2026-08-30）

> 回答「怎么确定排盘是准的」——不靠断言，靠可复现的校验。

## 一、基本立场：排盘不交给 LLM

八字四柱与紫微星曜**全部由确定性算法库计算**（lunar-javascript / iztro），LLM 只读不排。
但「用了库」不等于「排得对」——库可能选错、调用可能错、字段可能理解错（比如本项目踩过的 iztro 四化字段叫 `mutagen` 而非 `mutate`，就曾导致全部化禄化权丢失）。所以需要独立验证。

## 二、三层验证策略

| 层级 | 验证什么 | 手段 | 能否发现「库算错」 |
|---|---|---|---|
| **L1 结构性自检** | 六十甲子合法性、干支组合合法性 | 独立表 | 能（抓非法干支） |
| **L2 独立规则对拍** | 五虎遁月干、五鼠遁时干、时支与小时对应、日柱连续性、大运连续性与顺逆、紫微命宫公式、身宫口诀 | 自己实现的规则 vs 库输出 | 能（抓调用层与派生规则错误） |
| **L3 跨实现对拍** | 四柱、纳音、大运、起运年龄 | Node lunar-javascript × Python lunar-python | 部分（同作者不同实现，能抓版本/调用差异） |
| **依赖层（未独立验证）** | 节气精确时刻、农历朔望、紫微星曜布盘 | 库内含天文算法 | 否 |

## 四、诚实说明：哪些验证到了，哪些没有

**已验证（可放心）：**
- 四柱干支的**正确性**（跨实现一致 + 五虎遁/五鼠遁/时支映射全部自洽）
- 日柱序列连续无断点（连续 730 天逐日核对）
- 大运排布与顺逆规则
- 紫微**命宫与身宫的地支定位**（用独立公式与口诀表对拍，非依赖库自证）
- 晚子时换日处理的一致性

**未独立验证（属信任成熟实现）：**
1. **节气精确时刻与农历朔望**——这是天文历法层，短公式替代不了，依赖 lunar 库内置天文算法。该库是中文圈事实标准、被大量生产项目使用。**风险缓解**：月柱边界若算错会体现在五虎遁/月支上，抽样 3006 张（覆盖各月各年）未发现异常
2. **紫微十四主星的具体布盘**——只独立验证了命宫/身宫定位，星曜分布规则（依五行局查表排星）依赖 iztro。**风险缓解**：五行局格式、十二宫完整性、四化字段已做结构校验；已知踩坑（mutagen 字段）已修复并纳入回归校验
3. **神煞系统**——当前产品不用神煞定论，仅作标签，风险低

## 五、真实存在的准确性风险（必须让用户知道）

1. **子时流派**（影响最大）：23:00-24:00 出生，本项目默认**晚子时**（归次日，时柱按次日日干起算）。若用户师承「早子时」流派，结果会不同。**应当做成用户可选项**
2. **闰月处理**：紫微排盘对闰月出生者，iztro 的 `fixLeap` 参数决定按当月还是次月——流派有分歧，当前设为 `true`（闰月按当月）。校验时闰月样本（83 例）已跳过，属于**已知未覆盖区**
3. **真太阳时边界**：经度校正后若落在时辰交界 ±10 分钟内，输出会打 `boundaryRisk` 标记，但具体归哪个时辰仍需人工判断
4. **城市经度表**：内置 28 个城市，未覆盖的城市不做校正（会明确提示）

## 六、如何复跑

```bash
node src/verify-chart.js 3000    # L1+L2 自检（约 2 分钟）
node src/cross-check.js 1000     # L3 跨实现对拍（需 Python lunar-python）
```

任何排盘层改动，**改完必跑这两个脚本**，这是项目的回归门禁。
